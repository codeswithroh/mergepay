How it works

oracle.txt

GitHub is the oracle

Every Actions job can request an OIDC token, a JWT that GitHub signs with RS256. It names the repo, the event and the exact workflow that ran. MergePay checks that signature inside the contract using the modexp precompile.

threat-model.txt

Nothing to forge

The token's audience binds contract:issue:author. The bounty pins job_workflow_ref, and wallet links need actor_id == repository_owner_id. Relayers only pay gas.

why-arc.txt

Only makes sense on Arc

USDC is the gas token, so bounty, fee and payout are one asset. A contributor with a zero balance still gets paid. Blocks are final in under a second, so the payout comment lands moments after the merge.

README — trust model, honestly
  • GitHub's signing keys are registered by the contract owner, and anyone can check them against GitHub's JWKS. Moving this to a timelocked multisig is next.
  • Maintainers decide what gets merged. The workflow pays whoever authored the merged PR that closes the issue.
  • The award logic is public and pinned. award.yml is referenced by tag, and the bounty stores its hash.
