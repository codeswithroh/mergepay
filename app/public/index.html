Why it's trustless, and why Arc

GitHub is the oracle

Every Actions job can request an OIDC token, a JWT signed by GitHub with RS256. It names the repo, the event and the exact workflow file and commit that ran. MergePay checks that signature inside the contract using the modexp precompile, then reads the claims.

Nothing to forge

The token's audience binds contract : issue : author-id. The bounty pins job_workflow_ref, and wallet links require actor_id == repository_owner_id. Relayers only pay gas. They can't redirect funds.

Only makes sense on Arc

USDC is the gas token. Bounties, fees and payouts are all one asset, so a first-time contributor with a zero balance still gets paid. Blocks are final in under a second, so the payout comment lands on the PR moments after the merge.

Trust model, honestly
  • GitHub's signing keys are registered by the contract owner, and anyone can check them against GitHub's JWKS. Moving this to a timelocked multisig is the next step.
  • Maintainers decide what gets merged. The workflow pays whoever authored the merged PR that closes the issue. Pick bounties on repos you trust.
  • The award logic is public and pinned. award.yml is referenced by tag, and the bounty stores its hash.
